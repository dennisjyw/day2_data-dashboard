# 練習 2：Dashboard Brief 與需求澄清

## 目的

在開始新增儀表板功能前，先把目標使用者、使用情境、要支援的決策、核心問題與資料限制寫清楚，再請 AI 協助找出遺漏。這個練習只做產品定義與一輪澄清，不寫程式，避免還沒釐清問題就被畫面與技術實作綁住。

## 操作步驟

1. 開啟 `templates/dashboard-brief.md`，填寫目標使用者、使用情境、要支援的決策、核心問題、資料與指標、頁面結構。
2. 貼上「提示詞 1」，請 AI 根據 Brief 提出回饋與最多 5 個澄清問題。
3. 需要更嚴格檢查時，再貼上「提示詞 2」。
4. 完成至少一輪澄清後，將 Brief 存成下一練習會使用的 `dashboard-brief.md`。

## 提示詞 1：檢視 Dashboard Brief 並提出澄清問題

```text
我已完成 Dashboard Brief，內容如下：
[貼上你填好的 dashboard-brief.md 全文]

請先閱讀 README.md、AGENTS.md 與 data/data_dictionary.md，再依這些文件檢視我的 Brief。這一輪只做產品定義與需求澄清，請不要寫程式、不要新增資料欄位，也不要提出超出 README.md 專案限制的功能。

請回答：
1. 你從 Brief 看到哪些關鍵決策問題？
2. 每個問題適合用什麼量化指標？請說明分子、分母、期間與比較基準。
3. 頁面結構應該怎麼對應「結果、趨勢、診斷與待驗證假設、行動與追蹤」？
4. 我目前漏了哪些重要資訊、資料限制或隱私風險？

最多提出 5 個澄清問題。若資料字典沒有某個欄位或無法支持某個分析，請直接指出，不要自行補值或捏造欄位、日期、cohort 或因果結論。
```

## 提示詞 2：以嚴格顧問角度挑戰 Brief

```text
請扮演嚴格的校務研究顧問，依 README.md、AGENTS.md 與 data/data_dictionary.md 挑戰我的 Dashboard Brief。

請至少列出 3 個我不應忽略的問題，並對每個問題說明：
- 哪一段定義不夠具體；
- 可能造成什麼錯誤解讀；
- 應該補問或補寫什麼；
- 目前資料是否真的能支持它。

不要客套，也不要直接寫程式。特別檢查：分子與分母是否一致、整體率是否會被錯誤地算成各組率平均、比較基準是否清楚、資料是否為合成資料，以及是否把相關性寫成因果性。
```

## 驗收標準

- [ ] 主要使用者與使用情境清楚。
- [ ] 儀表板要支援的決策與決策週期清楚。
- [ ] 每個量化指標都能連回一個核心問題。
- [ ] 每個指標都寫出分子、分母、計算期間與比較基準。
- [ ] 資料粒度、資料限制與隱私風險有明確說明。
- [ ] 沒有把不存在的欄位、日期或 cohort 當成已知資料。
- [ ] 從 README.md 的專案限制整理至少 3 條非目標。
- [ ] 已完成至少一輪 Codex 澄清；不要求 AI 完全同意才可進入下一練習。
