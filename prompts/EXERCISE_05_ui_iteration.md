# 練習 5：UI、資訊層級與互動體驗

## 目的

在資料與功能正確後，改善目標使用者理解資訊與操作儀表板的速度。本練習不是單純美化畫面，而是讓使用者第一眼知道儀表板服務誰、最重要的指標是什麼、每個數字如何計算，並能在桌面與手機寬度下理解結果、趨勢與空資料狀態。

## 操作步驟

1. 貼上「提示詞 1」，依 Dashboard Brief 重新安排資訊層級。
2. 貼上「提示詞 2」，為量化指標補上計算方式與資料範圍。
3. 貼上「提示詞 3」，補上空資料與錯誤狀態。
4. 貼上「提示詞 4」，檢查手機版；若 AI 開始加入與決策無關的裝飾，使用「提示詞 5」拉回焦點。
5. 對照驗收標準，確認不用講師口頭補充也能理解頁面。

## 提示詞 1：調整資訊層級

```text
請先閱讀 data/data_dictionary.md 與 dashboard-brief.md，確認主要使用者、核心問題、資料限制與目前技術棧。請在既有 React 19 + Vite + TypeScript 專案上做最小必要的 UI 改善，不要重寫資料邏輯，也不要新增 UI framework。

請以資訊層級與目標使用者的理解速度為重點：
1. 從 Dashboard Brief 找出最重要的決策問題與量化指標，放在第一眼可見區。
2. 將次要指標放在第二層，並把年度趨勢與比較圖表放在能解釋指標的位置。
3. 將學年度、系所或招生管道篩選器放在清楚可找到的位置，且不破壞現有同步篩選邏輯。
4. 將明細放在需要深入查看的位置，讓使用者能從結果逐步下鑽到資料列。
5. 使用 Tailwind CSS 4 與既有 shadcn/ui 元件和設計 token；不要加入與決策無關的動畫、裝飾或新的元件庫。
6. 頁面文字要說明這是合成資料 prototype，且只能描述資料觀察與待驗證假設，不要寫成因果結論。

完成後請說明你如何把每個 UI 區塊對應到使用者問題，而不只是列出改了哪些顏色或字級。
```

## 提示詞 2：補充指標 tooltip

```text
請依 data/data_dictionary.md，為目前每個量化指標加入可理解的 tooltip 或等價說明。

每個指標至少要能查到：
- 指標名稱與明確分母，例如「錄取後註冊率」而不是只寫「註冊率」。
- 分子與分母的欄位。
- 計算期間與群體。
- 若為比例，清楚顯示是篩選後的 SUM(分子) ÷ SUM(分母)，不是各組率平均。

請沿用目前的 shadcn/ui 與 Tailwind CSS 4，不要改變原始資料或計算口徑，也不要用 tooltip 隱藏必要的主要資訊。完成後請檢查鍵盤與手機寬度下仍能理解說明。
```

## 提示詞 3：處理空資料與錯誤狀態

```text
請補上目前儀表板的空資料與錯誤狀態，不要改變既有資料邊界。

需求：
- 篩選後沒有資料時，顯示「目前篩選條件下沒有符合資料」，不要留下空白圖表或顯示 NaN、undefined、錯誤的 0。
- CSV 解析或資料載入失敗時，顯示「資料載入失敗，請重新整理或檢查資料來源」等使用者可理解的訊息。
- 技術錯誤可記錄供除錯，但畫面不要暴露內部路徑、環境設定、API key、密碼或 token。
- 錯誤狀態仍要保留「合成資料 prototype」的公開說明，不要自行產生替代數字。

請沿用現有 React、TypeScript、Tailwind CSS 4 與 shadcn/ui 結構，完成後列出測試空資料與載入失敗的方法。
```

## 提示詞 4：調整手機版

```text
請依目前 Dashboard Brief 調整手機版顯示，先檢查現有畫面再做最小必要修改。

請以約 375px 寬度驗證：
- 指標、圖表、篩選器與明細仍可閱讀與操作。
- 頁面不產生不必要的整頁橫向捲動。
- 篩選器在窄螢幕下可以收合或改成合理的垂直排列，但不能失去功能。
- tooltip、空資料狀態與合成資料標示不會被截斷。
- 不要為了手機版刪掉分子、分母、期間或群體等必要說明。

請繼續使用 Tailwind CSS 4 與 shadcn/ui，不要加入新的 CSS framework 或以固定假資料填補版面。
```

## 提示詞 5：避免加入無關裝飾

```text
請先停下目前的裝飾性 UI 修改，依 data/data_dictionary.md 與 dashboard-brief.md 重新檢查設計取捨。

請列出目前畫面上所有可能改變使用者解讀的視覺化選擇，例如指標分母、篩選狀態、座標軸、顏色語意、圖表標題與 tooltip。對每一項說明它回答哪個決策問題、使用者可能誤讀什麼，以及是否應保留。

請優先修正會造成錯誤結論的資訊層級或圖表問題，不要加入與決策無關的動畫、3D、雙軸或裝飾性圖表。不要把相關性寫成因果性。
```

## 圖表選擇原則

- 趨勢（時間軸）使用折線圖。
- 類別比較使用柱狀圖。
- 少於五類的結構占比才考慮占比圖；類別較多時優先使用柱狀圖。
- 個體或彙總明細列使用表格，不用圖表取代。
- 異常點要有可解釋的標示與 tooltip，不要只靠醒目顏色暗示原因。

## 校務研究的視覺誠實

- 整體率使用總分子 ÷ 總分母，不是各組率平均。
- 不混用人數、比例、率與平均值，也不以不適合的方式排序。
- 圖表標題說明指標、群體與期間。
- 不使用截斷座標軸放大差距、無法解釋的雙軸或 3D 圖表。
- 不把相關性寫成因果性；這個 prototype 只呈現觀察與待驗證假設。

## 驗收標準

- [ ] 第一眼能看出儀表板服務的主要使用者與情境。
- [ ] 第一眼能看出最重要的量化指標。
- [ ] 指標、圖表、篩選器、明細的資訊層級清楚。
- [ ] 不依賴講師口頭解釋也能理解分子、分母、期間與群體。
- [ ] 手機版至少可以閱讀與操作，沒有不必要的整頁橫向捲動。
- [ ] 沒有截斷座標軸、無法解釋的雙軸、3D 或難讀圖例。
- [ ] 沒有把相關性寫成因果性。
- [ ] 空資料與錯誤狀態有合理文字提示，不是空白或技術訊息。
